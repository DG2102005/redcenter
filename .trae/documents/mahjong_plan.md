## 三、分阶段实现计划

### 第一阶段：核心数据层与胡牌算法

#### 3.1.1 牌库数据构建 (`tile.ts`, `constants.ts`, `types.ts`, `tileAssets.ts`)
- 定义麻将牌类型系统：
  - 花色枚举：万(WAN)、筒(TONG)、条(TIAO)、字(HONOR)
  - 字牌细分：东、南、西、北、中、发、白
  - 牌值：万/筒/条为1-9，字牌为ESWN/ZFB
- 构建136张牌的牌库（34种 × 4张）
- **建立牌型↔图片资源映射表**（`tileAssets.ts`）：
  - 逐一核对34个美术文件的图片内容
  - 已确认：`图片拆解 (7).png`=八万、`图片拆解 (11).png`=二筒
  - 将9个已命名文件 + 24个"图片拆解"系列 + 1个tile文件 全部映射到34种标准牌型
  - 导出 `{牌型ID: 图片URL}` 字典供组件调用

#### 3.1.2 洗牌发牌算法 (`shuffle.ts`, `deal.ts`)
- 实现Fisher-Yates洗牌算法
- 实现逆时针发牌流程（庄家先发，每人13张）
- **防起手胡校验**：
  - 对四家手牌逐一检测
  - 若任意一家满足胡牌条件（14张，因庄家14张），重新洗牌
  - 循环直到四家均不满足起手胡条件
  - 校验超时保护（最多重试100次）

#### 3.1.3 手牌排列算法 (`sort.ts`)
- 实现需求中的排列规则：
  - 同类牌聚合：万子 → 筒子 → 条子 → 字牌
  - 同类升序：1→9
  - 字牌顺序：东→南→西→北→中→发→白
  - 红中作为字牌一员参与排序（排在最后或按需求）
- 使用稳定排序算法

#### 3.1.4 胡牌判定核心算法 (`win.ts`) - **重点**
这是项目最核心的算法，需要正确实现红中百搭机制。

**算法思路 - 递归拆牌法 + 红中分配：**
1. 统计手牌中红中的数量（0-4张）
2. 对非红中牌进行分组计数
3. 尝试将红中分配到各种可能的位置进行组合验证：
   - 将红中当作某种牌，检查是否能组成 4组搭子 + 1对将
   - 使用递归回溯法枚举所有红中的替代方案
4. 对每组方案验证标准胡牌型：
   - 4个面子（顺子/刻子/杠） + 1个将（对子）
   - 优先找将，再拆面子
   - 红中可参与将和面子的组成

**胡牌判定函数签名：**
```typescript
function checkWin(hand: Tile[]): boolean
// hand: 14张牌（含红中），判断是否符合推倒胡胡牌型
```

**听牌判定函数：**
```typescript
function checkTing(hand: Tile[]): Tile[]
// hand: 13张牌，返回所有可胡的牌型列表
```

### 第二阶段：游戏流程与规则引擎

#### 3.2.1 游戏状态机 (`gameEngine.ts`)
状态流转：
```
等待开始 → 洗牌 → 发牌 → 轮流摸牌 → 出牌 → 碰/杠/胡判定 → 下一玩家摸牌
                                                                    ↓
                                                              胡牌/流局判定
```

核心状态：
- `deck`: 剩余牌堆
- `players[4]`: 四位玩家状态（手牌、出牌区、碰杠区）
- `currentTurn`: 当前回合玩家
- `banker`: 庄家座位
- `phase`: 游戏阶段
- `winner`: 胡牌者

#### 3.2.2 回合流程控制
- 庄家判定：首局随机选庄，之后胡牌者为庄（流局不变）
- 摸牌顺序：逆时针（东→北→西→南）
- 摸牌后判定：是否听牌/是否自摸胡
- 出牌流程：玩家选牌打出 → 其他三家依次判定碰/杠/胡

#### 3.2.3 碰杠实现 (`rules.ts`)
- **碰**: 当其他玩家打出的牌与手中两张相同牌可组成刻子时
- **杠**: 
  - 明杠：手中有三张相同牌，他人打出第四张
  - 暗杠：手中已有四张相同牌（自摸）
  - 补杠：碰后摸到第四张
- 杠后补牌：从牌堆末尾补一张
- **限制**：不允许吃牌（chi）

#### 3.2.4 自摸与流局处理
- 自摸：摸牌后恰好满足胡牌条件
- 流局：牌堆剩余牌数为0仍无人胡牌
- 流局后自动开启新一局

### 第三阶段：AI决策引擎

#### 3.3.1 AI视野限制 (`aiEngine.ts`)
- AI仅可见：自己的手牌 + 桌面公共明牌
- AI不可见：其他玩家暗手牌、牌堆顺序
- AI内部维护一个"已见牌"表，用于概率计算

#### 3.3.2 AI决策逻辑
**模拟普通棋牌室玩家，非完美AI：**

1. **出牌决策**：
   - 计算每张手牌的"价值分数"
   - 优先打出孤张（无法与其他牌组成搭子的牌）
   - 其次打出边张（如1、9）
   - 红中作为百搭牌，除非必要绝不打出
   - 随牌局推进调整策略：
     - 前期（摸牌多）：进攻型，保留有潜力的组合
     - 中期：平衡型，攻守兼备
     - 后期（有人听牌）：保守型，打出安全牌

2. **碰杠决策**：
   - 碰杠后是否有利于手牌整体
   - 是否会导致手中留下孤张
   - 多家接近听牌时减少碰杠

3. **胡牌决策**：
   - 听牌后优先选择胡牌（自摸即胡）

4. **决策偏差模拟**：
   - 引入随机因子（5-10%概率做出非最优决策）
   - 偶尔漏碰、错打

## 四、关键算法设计

### 4.1 红中百搭胡牌算法（核心）

```
输入: 14张手牌 (含0-4张红中)
输出: 是否为胡牌型

步骤:
1. 统计红中数量 hongCount
2. 将非红中牌按花色和值分组计数
3. 使用递归尝试所有红中分配方案:
   - 对每种可能的红中替代组合进行验证
   - 验证: 能否组成 n对将 + m组面子 (n=1, m=4)
4. 对每种红中分配方案:
   a. 尝试每种牌作为"将"（对子）
   b. 剩余牌递归拆分为面子（顺子/刻子）
   c. 红中可作为面子中的任意一张
5. 任一方案成功 → 返回 true
```

### 4.2 AI出牌价值评估

```
对每张手牌计算"危险度"和"价值度":

价值度:
- 刻子: 100分
- 顺子中的牌: 80分
- 对子: 60分
- 搭子(两面/嵌张): 40分
- 边张搭子: 20分
- 孤张: 0分
- 红中: 200分 (百搭，不轻易打出)

危险度(牌局后期):
- 已打出过的牌: 安全
- 多张已出现: 较安全
- 从未出现: 危险
```

## 六、风险处理

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| "图片拆解"系列文件名不直观 | 映射易错 | 实现阶段逐一核对图片内容建立映射表，已确认2项(八万=图片拆解7，二筒=图片拆解11)，建立后做全量校验 |
| 红中百搭算法复杂度 | 性能问题 | 对红中数量进行剪枝优化，最多4张红中时枚举量可控 |
| AI决策性能 | 体验卡顿 | AI操作采用异步处理，不阻塞UI渲染 |
| 起手胡校验死循环 | 无法开始游戏 | 设置最大重试次数(100)，超限后自动调整发牌策略 |
